## Scope

This restore point addresses only the Windows build infrastructure failure caused by an inconsistent `sqlite3` native-assets cache. No business logic, scenario logic, signing, flavor, environment, IDE configuration, or runtime UI was changed.

## Failure identified before recovery

The verbose Flutter build reported that the current native-assets manifest expected:

```text
C:\Projekti\OPC\OPC v.1\SOURCE\.dart_tool\hooks_runner\shared\sqlite3\build\download-16979859\sqlite3.dll
```

That file was missing. Older hash directories remained in the same generated cache, so the cache was present but stale and inconsistent. Flutter then failed while copying the missing source DLL to `build\\native_assets\\windows\\sqlite3.dll`; MSBuild surfaced the child failure as `MSB8066`.

## Controlled recovery

With no Flutter, Dart, MSBuild, or CMake process holding the cache, only generated directories inside `SOURCE` were removed:

```text
.dart_tool\\hooks_runner\\shared\\sqlite3\\build
.dart_tool\\flutter_build
build\\native_assets\\windows
build\\windows\\x64
```

The project source, dependency declarations, global Pub cache, build logs, and tracked files were not removed or modified. The generated directories were regenerated by the subsequent manual Windows release build.
