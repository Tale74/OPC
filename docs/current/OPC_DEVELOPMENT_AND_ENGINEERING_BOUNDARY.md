## Protected workflow

- Establish OWNER authority, continuity, current documentation and scope before substantive work.
- Keep business authority, as-built source behavior, tests, runtime observation, release and publication as separate statuses.
- Use source-learning read-only when reconstructing current technical behavior; source and tests cannot create business policy.
- Keep primary mixed SOURCE forensic-only when the task scope identifies it as such.
- Keep canonical/private runtime databases read-only unless a separately authorized disposable-copy workflow applies.
- For code/config/schema/build work, use the sequential targeted-test → analyzer → full-test → authorized-build gates; documentation-only work is validated through documents, links, disposition and evidence structure.
- Do not commit, push or publish without explicit authorization.
