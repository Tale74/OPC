## 10. Kritični reconciliation nalazi

1. `docs/GIT_WORKFLOW_ARC.md` još nalaže grananje sa `main`, dok owner-approved plan bira operativni `develop/opc-v1`; closure mora ukloniti konflikt.
2. `docs/OPC_PURPOSE_AND_ANTI_DRIFT_MANIFEST.md` sadrži privatnu apsolutnu runtime putanju u odeljku canonical database policy; javni tekst mora dobiti sanitizovanu formulaciju bez promene data-ownership odluke.
3. `docs/OPC_CURRENT_DEVELOPMENT_STATE.md` i `docs/OPC_IMPLEMENTATION_STOP_LIST.md` predstavljaju stariji razvojni trenutak i moraju biti prepisani prema autoritativnom dependency planu.
4. Aktivni Git tree sadrži plan draft/review ciklus, duple root/task reportove i Web/sync future-scope dokumente koji mogu uticati na source-learning uprkos tome što OPC Web nije current scope.
5. Lokalni `PROJECT_DOCS` sadrže vredne owner odluke pomešane sa sprovedenim taskovima, starim SaaS/package/licensing formulacijama, lokalnim putanjama i istorijskim operativnim pravilima.
6. Jedanaest lokalnih kontrolnih fajlova duplirano je byte-identično u dva aktivna lokalna foldera, što nepotrebno stvara dva kandidata za authority.

## 11. Obavezna zaštita pre brisanja

Pre uklanjanja bilo kog kandidata closure task mora:

1. mapirati svaku još važeću owner odluku na autoritativni naslednik;
2. mapirati jedinstveni migration/JSON/backup/PREDMET dokaz na zadržani dokument ili source/test dokaz;
3. zapisati originalni SHA-256 i razlog uklanjanja;
4. proveriti da nijedan aktivni Markdown link ne ostaje slomljen;
5. ažurirati source-of-truth mapu, manifest, current state, stop-list, Git workflow i owner decision index;
6. semantički sinhronizovati odobreni autoritativni plan u jedini kontrolisani lokalni dokumentacioni izvor;
7. sprečiti budući source-learning iz `SOURCE_PROJECT_DOCS`, dupliranog `LOCAL_PROJECT_DOCS` i ignorisanih root dokumenata.

## 12. Predloženi fizički model posle closure-a

- Git `docs/` postaje jedini aktivni autoritativni dokumentacioni source.
- Lokalno ostaje jedna kontrolisana semantička kopija autoritativnog skupa, sa document ID/version/hash registrom.
- `SOURCE/PROJECT_DOCS`, dupli lokalni `PROJECT_DOCS` i ignorisani root dokumenti prestaju da budu aktivni source-learning folderi.
- Istorijski task rezultat čita se iz Git istorije po branch/SHA/report lineage-u, ne iz 66 aktivnih report fajlova.
- Privatni runtime, backup, restore i test-data folderi ostaju van javne dokumentacije i van ovog removal taska.
